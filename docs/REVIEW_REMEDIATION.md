# 初审意见整改路线

## 2026-10-22 第二轮意见与实际改进

本次意见针对高度依赖手写模型和重置环境、OpenAPI 覆盖不足、模拟场景多而真实接入证据少，以及相对 Schemathesis 的增量价值不足。不能只扩充申报措辞。

本轮新增 MoonBit `crud_plan` 与受限归属 runner：以集合路径和字段两项选择生成六步，不写状态机、不要求全局 reset；创建响应捕获 ID，写入与清理前核验随机标记，无法归属/不稳定/清理失败均不能报全通过。显式业务模型仍保留，用于不是普通 CRUD 的库存等不变量。

扩展同类本地参数、请求体、响应和 Schema 引用（含转义与循环拒绝），缺省 operationId、读写属性方向语义。仍未实现完整 OpenAPI、一般依赖图或业务含义自动推断，公开标记保持 false。

独立上游 PocketBase 0.40.5 实际 SQLite 接入：两类集合各三轮，保留哨兵并重启验证；接口契约和资料是合成测试用的，不冒充官方完整 OpenAPI 或真实用户项目。Windows 自动目录删除失败保留原始事实；明确保留模式可复现业务断言，默认清理完整性仍以 CI/环境为准。见 [证据](INTEGRATION_EVIDENCE.md)。

[Schemathesis 对照](COMPARISON.md) 明确承认对方已有自动依赖、状态检查、缩减能力与更广生态；本项目定位于 MoonBit 可复用核心与窄范围低配置归属回归，不能声称独有、全面替代或性能领先。未进行双方同条件检出率实测；真实业务接入授权、全标准兼容和更强量化对照仍是未完成项。不得保证本轮即通过复审。

## 第一轮范围与长期目标

初审指出：扣除契约校验与通用测试设施后，独立行为引擎的核心范围不足；需说明状态依赖及失败缩减机制、附实际案例，并避免把 OpenAPI 子集称为完整支持。

选择的长期路线是完整 OpenAPI 3.0 JSON 兼容与独立状态行为引擎并行推进。完整兼容是待验收目标，不是当前既成事实；不能靠改名、少量示例或只增加“不支持”文字消除缺口。

本轮先补核心差异能力：声明式模型状态、跨步骤值断言、依赖校验、确定性状态驱动序列生成、每次重放前显式重置、同故障指纹验证、保持依赖的序列缩减，以及契约全部通过但业务状态错误的反例。

随后按官方规范形成完整兼容矩阵：引用与循环、组合/约束/读写语义、参数各位置及序列化、媒体/编码、响应/链接/回调、安全方案、服务地址与错误诊断。每个单元需正例、拒绝/边界、端到端和跨目标消费证据。完成前仍公开称为实验性 OpenAPI 适配，不宣称已全标准兼容。

私人申报书的修订草稿与实际代码证据分开，不自动替用户重新报名，不保证复审结论。公开仓库和注册表的修改/发布分别核对授权，不公开私人申报资料、令牌和运行报告。
