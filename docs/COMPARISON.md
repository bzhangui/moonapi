# 与 Schemathesis 的定位对照

针对本次“接入成本高、通用性和增量价值不足”的反馈，先承认：自动生成请求、串接真实 ID、状态测试和缩减并非 MoonAPI 独有。不能把其它工具已有能力重新命名为创新。本页为 2026-10-22 依据官方文档的功能核对，**不是双方同条件性能/缺陷检出率实测**。

| 方面         | Schemathesis 官方能力                               | MoonAPI 0.3.0 源码现状                                                                                  |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 自动依赖分析 | schema、响应 URL、显式 Links；包括嵌套和组合 schema | 只有无歧义 REST CRUD 约定；需选择集合与字段，尚不支持一般资源依赖图/Links                               |
| 状态检查     | 创建可用性、删除后访问等内置检查；可扩展            | 自动 CRUD 读回持久化/删除检查；复杂业务用显式模型断言，不声称独有                                       |
| 状态与重放   | 基于 Hypothesis 的状态机、测试定制钩子              | MoonBit 状态/依赖验证和候选生成；适配器执行相同指纹重放，清理失败或不稳定结果不确认                     |
| 接入与隔离   | 支持定制初始化、认证、清理                          | 新 CRUD 档不写状态机、不需全局 reset；仅在已捕获 ID 与随机标记核验通过时修改/清理，不能保证全局业务隔离 |
| 规范广度     | 已有更广的标准、媒体、认证、GraphQL 等能力          | 明确的 OpenAPI 3.0 JSON 子集；本轮扩展常用引用、缺省操作 ID、读写属性，不是全标准兼容                   |
| 生态/分发    | Python CLI、pytest 与成熟工具链                     | MoonBit 纯计算核心四目标 API；Node HTTP 适配；不复制 Python 框架源码                                    |

实际的增量定位是：让 MoonBit 项目能直接复用核心状态、断言与缩减库；在符合约定的资源接口上以较少配置运行有归属限制的持久化回归；不擅自清空共享测试库。它是较窄的工程组合优势，不是对 Schemathesis 的全面替代或性能领先证明。

接入成本也不能省略：用户仍需有效且受当前适配支持的接口描述、测试授权、一个可写探测字段，以及处理副作用/遗留数据的方案。本轮 PocketBase 的 OpenAPI 适配契约由本项目编写；不能据此宣称“任意真实系统零配置”。复杂库存、余额、异步一致性仍需业务模型和隔离设施。

后续评估应在相同版本、种子、预算、正常/缺陷对照、隔离策略下实际运行两个工具，分别报告假阳性、稳定复现率、接入配置量及清理副作用。未做该实验前不写“检出率更高”“缩减更强”“其它工具不能发现”。

主要依据：[Schemathesis 状态测试说明](https://schemathesis.readthedocs.io/en/stable/explanations/stateful/)、[内置检查](https://schemathesis.readthedocs.io/en/stable/reference/checks/)、[状态测试定制](https://schemathesis.readthedocs.io/en/stable/guides/stateful-testing/)。本项目对应实现见 `core/crud.mbt`、`core/stateful.mbt`、`platform/owned-crud.mjs` 与对应测试。
